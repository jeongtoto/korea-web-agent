# v0.7 Shopping Intelligence Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a cloud-first precision recommendation pipeline that discovers 20–50 products, filters hard constraints, enriches specs/reviews, deeply researches Top 5, reuses v0.6.2 exact-price verification for finalists, and returns evidence-backed value rankings without making PC Relay a prerequisite.

**Architecture:** Preserve v0.6.2 as the authoritative exact-product purchase verification engine. Add a new `src/shopping/` domain with narrow modules for query planning, discovery, normalization, constraint gating, review intelligence, ranking, and orchestration. Recommendation score and evidence confidence are separate. Relay remains an optional personalized-purchase overlay and cannot change the public recommendation ordering.

**Tech Stack:** Node.js >=22, TypeScript 5.8.3 strict mode, built-in `node:test` + `node:assert/strict`, existing DuckDuckGo discovery, existing v0.6.2 Provider v2, Netlify Background Functions, `@netlify/blobs` 10.7.13. No new runtime dependency unless a failing fixture proves it is necessary.

**Spec:** `docs/superpowers/specs/2026-08-26-v0.7-shopping-intelligence-design.md`

## Global Constraints

- Work only on `feature/v0.7-shopping-intelligence`; do not modify `main` directly.
- Preserve `POST /api/agent/research` and `GET /api/agent/job?jobId=...` contracts.
- Preserve exact-product behavior and v0.6.2 reliability blockers.
- Relay offline must never lower or reorder the public product-quality recommendation.
- Search metadata is discovery-only and never a decisive public purchase price.
- A verified hard-constraint failure excludes a candidate; cheaper price cannot override it.
- Recommendation score and evidence confidence are independent outputs.
- Unknown shipping reduces price confidence only, not product-quality confidence.
- Full 13-provider verification is limited to Top 3 by default and Top 5 only under explicit escalation conditions.
- All material Top-5 claims must carry evidence provenance.
- No runtime dependency is added in the first implementation pass.
- Every production behavior change follows TDD: failing test -> verify RED -> minimal implementation -> verify GREEN -> regression tests.
- Final gate: full tests, typecheck, build, dependency audit, Golden TV/Bedding scenarios, and v0.6.2 regression suite.
