# v0.7.4 Seller Verification Graduation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Increase decisive public price verification by resolving comparison-site seller targets into real seller pages and verifying exact bundle, current price, shipping, availability, and mandatory fees without weakening existing evidence gates.

**Architecture:** Add a bounded seller-resolution pipeline used by comparison providers: deterministic static/embedded seller extraction, safe redirect resolution, exact-identity fallback discovery, then the existing direct seller-page verification path. Keep comparison/search prices indicative only; seller-page facts remain authoritative. Add structured verification trace and mandatory-fee status as backward-compatible optional fields.

**Tech Stack:** TypeScript, Node.js built-in test runner via existing npm scripts, Netlify Functions, existing provider registry/direct-page fetch stack, no new runtime dependency, no browser runtime.

**Spec:** `docs/superpowers/specs/2026-08-27-v0.7.4-seller-verification-graduation-design.md`

## Global Constraints

- Unknown shipping is never treated as zero and never becomes decisive.
- Search metadata, comparison metadata, and redirect query parameters are never decisive offer evidence.
- Seller-domain current facts outrank comparison-page advertised facts.
- Exact identity, exact required bundle, eligible hard constraints, known shipping, non-unavailable state, and resolved mandatory-fee state are required for an eligible decisive seller offer.
- Relay-personalized state must not change public seller resolution, public total cash price, public winner/history, or public verification trace.
- No new browser-runtime requirement, LLM extraction, crawler service, or external runtime dependency.
- Provider/network work remains bounded by existing `ProviderBudget.sellerExpansion` and shared verification cache.
- Every new heuristic requires deterministic fixture/test coverage.
- Release version target is `0.7.4` only after functional verification is green.

- [ ] **Step 3: Implement deterministic embedded extraction**

In `seller-resolution.ts`:
- parse only JSON-bearing `<script>` blocks and explicit `data-*` seller URL attributes,
- recursively walk plain objects/arrays,
- accept URL keys from a fixed allowlist such as `url`, `sellerUrl`, `mallUrl`, `outlink`, `link`,
- accept seller/product/price/shipping keys from fixed allowlists,
- normalize relative URLs against `baseUrl`,
- require HTTP/HTTPS and `assertPublicUrl`,
- never infer seller facts from arbitrary free text.

Use a bounded recursive walk:

```ts
function walk(value: unknown, depth = 0): Record<string, unknown>[] {
  if (depth > 8) return [];
  if (Array.isArray(value)) return value.flatMap((item) => walk(item, depth + 1));
  if (!value || typeof value !== 'object') return [];
  const object = value as Record<string, unknown>;
  return [object, ...Object.values(object).flatMap((item) => walk(item, depth + 1))];
}
```
