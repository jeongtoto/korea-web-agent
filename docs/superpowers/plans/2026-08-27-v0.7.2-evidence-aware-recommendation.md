# v0.7.2 Evidence-aware Recommendation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Improve Shopping Intelligence recommendation quality by making preliminary finalist selection evidence-aware, calibrating review trust, modeling value under price uncertainty, and emitting deterministic recommendation tiers/rationale without weakening v0.7.1 price or Relay safety.

**Architecture:** Preserve the existing discovery -> normalization -> light enrichment -> deep research -> price verification -> ranking pipeline. Add three leaf modules (`preliminary-ranking.ts`, `review-trust.ts`, `value-model.ts`) with no network access, then have `shopping-orchestrator.ts` and `ranking.ts` compose them. Provider v2 and Relay contracts remain unchanged.

**Tech Stack:** Node.js >=22, TypeScript 5.8.3 strict mode, built-in `node:test`, Netlify Functions/Background Functions, existing Provider v2 and Relay modules. No new runtime dependency.

**Spec:** `docs/superpowers/specs/2026-08-27-v0.7.2-evidence-aware-recommendation-design.md`

## Global Constraints

- Work only on `feature/v0.7.2-evidence-aware-recommendation` until final merge.
- Do not change Provider v2 decisive-offer gates or Relay authentication/signing/public-personalized isolation.
- Search metadata never becomes decisive price evidence or purchase-verified review evidence.
- `recommendationScore` and `evidenceConfidence` remain distinct signals.
- Relay availability must not change public recommendation order, score, tier, or best-value eligibility.
- Every heuristic change requires a deterministic regression test.
- No external LLM, vector DB, crawler runtime, or other runtime dependency is added.
- Final release gate is fresh install/audit/full test/typecheck/build, PR review, main CI, production smoke.
