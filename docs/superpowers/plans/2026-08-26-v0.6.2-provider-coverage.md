# Korea Web Agent v0.6.2 Provider Coverage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade the public Cloud research path so 13 required Korean commerce channels can discover exact products, follow comparison portals to downstream sellers, verify exact identity, price, mandatory shipping, promotion validity, and purchasable state, deduplicate duplicate seller offers, and rank only verified total-cash economics without weakening v0.6.1 reliability gates.

**Architecture:** Keep the v0.6.1 canonical identity, hard-constraint, response-validation, public-history, Relay-isolation, and Action contracts authoritative. Add a hybrid Provider Adapter layer between discovery and the existing offer engine. Comparison portals emit seller candidates rather than decisive prices. Market-specific extractors run inside the existing SSRF-safe direct-page fetcher and fall back to generic JSON-LD/static extraction. Request-scoped verification cache and bounded concurrency prevent duplicate seller fetches and whole-job stalls. Public unconditional cash and public conditional economics are ranked separately.

**Tech Stack:** Node.js >=22, TypeScript 5.8.3 (`strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`), built-in `node:test` + `node:assert/strict`, Netlify Functions/Background Functions, `@netlify/blobs` 10.7.13, existing DuckDuckGo public discovery, existing Local Relay unchanged.

**Spec:** `docs/superpowers/specs/2026-08-26-v0.6.2-provider-coverage-design.md`

## Global Constraints

- Create `feature/v0.6.2-provider-coverage` from the approved design branch only after `git merge-base --is-ancestor main design/v0.6.2-provider-coverage` succeeds. Do not implement source code on the design branch.
- Preserve `POST /api/agent/research` / `operationId: startProductResearch` and `GET /api/agent/job?jobId=...` / `operationId: getProductResearchResult`.
- Preserve `queued -> running -> completed|partial|failed`; provider-local failure may produce a `partial` job but must not force system-level `failed` when other verified evidence is usable.
- Preserve v0.6.1 exact identity, hard constraints, search-metadata exclusion, unknown-shipping exclusion, alternative-condition isolation, public-history safety, Relay identity safety, request-scoped purchase context, and response-validator blockers.
- `search_metadata` and comparison-site advertised prices are discovery evidence only.
- Omitted/착불/판매자 문의/지역별 미확정 mandatory cost is never interpreted as free shipping.
- Public providers never infer account-only, friend-only, membership-only, saved-wallet, or personalized prices.
- AliExpress and Temu are excluded from the required v0.6.2 Provider Registry and the default required-commerce plan.
- KREAM, used/refurb/offline, reviews, community, news, and academic sources may remain as legacy supporting evidence, but they do not count as required Provider Registry coverage.
- Keep `standardPriceRows` in its existing four-row order. Add `bestOffers.publicConditional` without reinterpreting the existing stable rows.
- Add no runtime dependency. Use fixture-driven parsers and existing URL/retry policy.
- Follow TDD for every behavior change: failing test -> prove RED -> minimal implementation -> prove GREEN -> commit.
- Before changing Netlify-specific functions/workflows, retrieve current Netlify coding context. Never expose environment-variable values or secret metadata.
- Final verification is fresh `npm ci`, production audit, full tests, typecheck, and build.
