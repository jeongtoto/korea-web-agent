# Korea Web Agent v0.6.2 Provider Coverage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade the public Cloud research path so 13 required Korean commerce channels can discover exact products, follow comparison portals to downstream sellers, verify exact identity, price, mandatory shipping, promotion validity, and purchasable state, deduplicate duplicate seller offers, and rank only verified total-cash economics without weakening v0.6.1 reliability gates.

**Architecture:** Keep the v0.6.1 canonical identity, hard-constraint, response-validation, price-history, Relay-isolation, and Action contracts authoritative. Add a hybrid Provider Adapter layer between discovery and the existing offer/ranking layer. Comparison portals produce seller candidates rather than decisive prices. Market-specific extractors feed a generic direct-page fallback. Request-scoped verification cache and bounded concurrency prevent duplicate fetches and whole-job stalls. Public unconditional cash and public conditional economics are ranked separately.

**Tech Stack:** Node.js >=22, TypeScript 5.8.3 with `strict`, `noUncheckedIndexedAccess`, and `exactOptionalPropertyTypes`, built-in `node:test` + `node:assert/strict`, Netlify Functions/Background Functions, `@netlify/blobs` 10.7.13, existing DuckDuckGo public discovery, existing Local Relay unchanged.

**Spec:** `docs/superpowers/specs/2026-08-26-v0.6.2-provider-coverage-design.md`

## Global Constraints

- Implement on `feature/v0.6.2-provider-coverage`, created from the approved design branch after verifying it still descends from current `main`; do not implement source code directly on `design/v0.6.2-provider-coverage`.
- Preserve `POST /api/agent/research` / `operationId: startProductResearch` and `GET /api/agent/job?jobId=...` / `operationId: getProductResearchResult`.
- Preserve `queued -> running -> completed|partial|failed`; provider failures are isolated and must not turn a usable multi-market job into a system failure.
- Preserve v0.6.1 exact identity, hard-constraint, search-metadata, unknown-shipping, alternative-condition, public-history, Relay identity, purchase-context, and response-validator gates.
- Keep `search_metadata` and comparison-site advertised prices non-decisive.
- Never infer free shipping from an omitted field. Unknown/착불/판매자 문의/지역별 미확정 mandatory cost keeps total cash unresolved.
- No public provider may infer account-only, friend-only, membership-only, saved-wallet, or personalized prices.
- AliExpress and Temu are not v0.6.2 required providers and must be removed from the default required-commerce plan. Existing unrelated legacy parsing may remain if it is not used by the v0.6.2 required Provider Registry.
- KREAM, used/refurb/offline, review, community, news, and academic discovery may remain as legacy supporting sources, but they do not count toward the required 13 Provider Registry rows.
- Keep `standardPriceRows` backward-compatible with its existing four-row order. Surface `publicConditional` through Best Offers/presentation rather than silently reinterpreting the old `card` row.
- No new runtime dependency is required. Prefer focused TypeScript helpers and fixture-driven parsers.
- Use TDD for every behavior change: write the failing test, run it and observe RED, implement the minimum change, rerun and observe GREEN, then commit.
- Before modifying Netlify-specific function/workflow behavior, retrieve the current Netlify coding context and follow it. Do not expose environment-variable values or secret metadata.
- Final verification requires `npm ci`, `npm audit --omit=dev --audit-level=high`, `npm test`, `npm run typecheck`, and `npm run build` with fresh output.
