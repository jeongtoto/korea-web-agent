# v0.7.1 Live Verification Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make KWA's live exact-product verification dependable enough that direct URLs, shipping economics, comparison-market seller expansion, and Relay availability can be trusted without weakening the v0.7 Shopping Intelligence recommendation layer.

**Architecture:** Keep Provider v2 authoritative and make narrow fixes at existing module boundaries. Direct-page extraction owns page facts, market extractors add site-specific facts, seller expansion remains the only path that upgrades discovery metadata to page-verified offers, and Relay diagnostics remain informational rather than affecting public ranking.

**Tech Stack:** TypeScript 5.8, Node.js 22, Netlify Functions/Background Functions, existing Provider v2/Relay modules, node:test.

**Spec:** `docs/superpowers/specs/2026-08-26-v0.7-shopping-intelligence-design.md`

## Global Constraints

- No search-metadata offer may become a decisive purchase winner.
- Unknown shipping must never be treated as free.
- Direct exact-product URLs must not regress below equivalent discovery identity evidence.
- Relay unavailability must not change public recommendation ranking.
- Provider-local failures must remain isolated.
- Existing v0.6.x/v0.7.0 regression suites remain mandatory.
- No browser runtime is added to the Netlify cloud path in this release.
- Release metadata is updated by normal repository file changes only; do not create one-shot release workflows.
