# v0.7.2 Evidence-aware Recommendation Design

## Goal

Improve Shopping Intelligence recommendation quality without weakening the v0.7.1 exact-price verification engine or Relay isolation guarantees.

The release focuses on four quality bottlenecks:
1. finalist selection before deep research,
2. review evidence trust/calibration,
3. value ranking under price uncertainty,
4. recommendation explanation and confidence semantics.

## Non-goals

- Do not change Provider v2 decisive-offer gates.
- Do not change Relay authentication, signing, or public/personalized price separation.
- Do not add an external LLM, vector database, or browser crawler runtime.
- Do not expand to new product categories in this release.
- Do not let search metadata become decisive product, review, or price evidence.

## Current bottlenecks

### Finalist selection

The current orchestrator shortlists candidates primarily by hard-constraint state and discoveryScore before deep research. This can over-favor products with stronger search exposure rather than products with stronger verified specifications and evidence diversity.

### Review evidence

Deep research currently converts search-result title/snippet text into qualitative evidence. A commerce-domain search hit may be treated as verified-purchase-like evidence even when the search result itself does not prove a verified purchase. Recency is not calibrated, and independence is primarily URL-path based.

### Value calculation

Value is currently cohort-relative price normalization with a neutral fallback for missing price. This can overstate value for candidates whose prices are not actually verified.

### Recommendation interpretation

recommendationScore and evidenceConfidence are already separate, which is correct, but the final result lacks an explicit recommendation tier that distinguishes strong recommendation from promising-but-under-evidenced candidates.

## Architecture

Keep the existing pipeline:

Query Planner -> Broad Discovery -> Normalization -> Light Enrichment -> Preliminary Selection -> Deep Research -> Exact Price Verification -> Final Ranking

Add three focused modules and extend one existing module:

1. `preliminary-ranking.ts`
   - selects deep-research finalists using evidence-aware preliminary quality rather than discoveryScore alone.
2. `review-trust.ts`
   - computes source trust, identity relevance, independence, sponsorship penalty, and recency factor.
3. `value-model.ts`
   - computes quality-adjusted value with explicit price uncertainty.
4. `ranking.ts`
   - consumes the above signals and emits recommendation tier and structured rationale.

Existing `review-intelligence.ts` remains responsible for topic/polarity extraction and topic-level consensus. Trust calibration is kept separate so topic parsing and source trust do not become tangled.

## 1. Evidence-aware preliminary selection

### Purpose

Choose the 8-10 shortlist and Top 5 deep-research finalists based on evidence quality, not search prominence.

### Inputs

For each candidate:
- hard-constraint state,
- discovery score,
- count and class of verified facts,
- official facts,
- source diversity,
- known model identity,
- preliminary price evidence availability,
- category-specific quality facts.

### Preliminary score

Conceptual formula:

`preliminaryQuality = fitGate + verifiedSpecQuality + sourceDiversity + identityStrength + categoryPotential + smallDiscoveryPrior`

Rules:
- EXCLUDED candidates never enter shortlist.
- ELIGIBLE outranks PRELIMINARY.
- discoveryScore contributes at most 10% of the preliminary score.
- verified page/official facts must outweigh search prominence.
- source diversity is capped to prevent evidence spam.
- missing price does not exclude a product at this stage.

The Top 5 deep-research finalists come from this score, not raw discovery order.

## 2. Review Trust Engine

### Trust dimensions

Each review evidence item receives:
- `sourceTrust`
- `identityRelevance`
- `independenceConfidence`
- `recencyFactor`
- `sponsorshipFactor`
- `verifiedPurchaseConfidence`
- `effectiveWeight`

### Source trust

Search metadata itself is never equivalent to a verified-purchase review.

Trust ordering:
1. directly verified purchase review evidence,
2. independent long-form user/community report,
3. editorial review,
4. ordinary search snippet describing a review,
5. sponsored content.

A Coupang/Naver Shopping URL alone is not sufficient to set verified purchase confidence to 1.0.

### Identity relevance

Review evidence must match the candidate identity.

Levels:
- exact model + variant/bundle: 1.0
- exact model, variant unclear: 0.8
- family/series only: 0.5
- generic category claim: <=0.25

Generic claims may inform context but cannot strongly affect candidate ranking.

### Recency

Use a bounded decay, not a hard cutoff.

Suggested defaults:
- <=180 days: 1.0
- 181-365 days: 0.9
- 1-2 years: 0.75
- >2 years: 0.6
- no date: 0.7

Recent repeated quality regressions should outweigh a much older positive review set when source quality is comparable.

### Independence

Do not count evidence independently solely because the URL differs.

Normalize an independence signature from:
- canonical host,
- author/channel/store identity when available,
- normalized claim fingerprint,
- source URL path.

Near-identical claims from the same host/author family should collapse or receive sharply diminishing weight.

### Sponsorship

Sponsored evidence is not discarded, but:
- cannot alone produce HIGH review confidence,
- cannot outweigh multiple independent user reports,
- is explicitly surfaced in rationale when material.

## 3. Value model

### Principle

Value means quality-adjusted purchase merit, not cheapest price.

Conceptual form:

`value = meritAdjusted / priceBurden`

Where `meritAdjusted` combines category score and evidence confidence, and `priceBurden` uses verified public cash when available.

### Price states

- `verified`: decisive public cash price available.
- `indicative`: exact-enough page price but not decisive.
- `unknown`: no trustworthy candidate price.

Rules:
- verified price can drive the main value score.
- indicative price can inform value with a confidence penalty.
- unknown price cannot produce a "best value" claim.
- missing price must not receive the same neutral value as a verified mid-market price.
- small price differences cannot erase large quality differences.

The price engine remains unchanged. This module only consumes its output.

## 4. Final ranking and recommendation tier

Keep:
- `recommendationScore`
- `evidenceConfidence`

Add:
- `recommendationTier`
- `rationale`

Tiers:
- `STRONG_RECOMMENDATION`
  - high score, sufficient evidence, no critical uncertainty.
- `RECOMMENDED`
  - good score and adequate evidence.
- `PROMISING_NEEDS_VERIFICATION`
  - good product merit but meaningful evidence/price uncertainty.
- `CAUTION`
  - material repeated negatives or weak value despite eligibility.

Rules:
- Tier never changes hard-constraint eligibility.
- Unknown decisive price blocks STRONG_RECOMMENDATION for value-led queries.
- Repeated independent material negatives cap the tier.
- Relay availability never changes public recommendation score, tier, or order.

## 5. Structured rationale

Replace raw internal dimension-name explanations with structured fields that GPT can explain directly:

- `whyItRanks`
- `bestFor`
- `tradeoffs`
- `evidenceGaps`
- `repeatedNegativeTopics`
- `priceStatus`

All claims must have provenance URLs already present in candidate/review/offer evidence.

## 6. Category behavior

v0.7.2 improves only:
- `portable_display`
- `bedding`

No new category schemas are added.

Category-specific facts remain distinct.

Portable display priorities include:
- display quality,
- mobility/stand stability,
- smart features,
- build/durability,
- service/warranty,
- value.

Bedding priorities include:
- material/fill quality,
- tactile comfort,
- seasonal comfort,
- care,
- durability,
- allergy/dust behavior,
- value.

## 7. Error handling and partial results

- Candidate-local enrichment/review failures remain isolated.
- Deep research failure for one finalist does not discard others.
- Review trust calculation is deterministic and cannot throw for malformed dates/URLs.
- If review evidence is sparse, candidate remains rankable with lower evidenceConfidence and a visible evidence gap.
- If price is unavailable, candidate remains rankable for product merit but cannot be labeled best value.

## 8. Regression invariants

The following v0.7.1 invariants must remain true:
- wrong SKU never wins decisive price,
- wrong bundle never wins,
- unknown shipping never produces decisive cash,
- search metadata never wins decisive price,
- Relay personalized price never contaminates public ranking/history,
- Relay online/offline never changes public recommendation order,
- exact-product requests continue using the exact verification path,
- unsupported recommendation categories continue using the legacy path.

## 9. Golden quality benchmarks

Add deterministic fixtures/tests for:

1. **Quality beats modest price gap**
   - 359k mediocre TV vs 399k materially better TV.
   - Better TV should rank first when user values image quality/mobility.

2. **Search popularity does not dominate**
   - Candidate A has high discoveryScore but weak verified facts.
   - Candidate B has lower discoveryScore but strong official/page evidence.
   - B must enter Top 5 ahead of A.

3. **Sponsored volume does not dominate**
   - five sponsored positive posts vs two independent user reports.
   - sponsored volume must not create higher confidence/consensus.

4. **Duplicate complaint collapse**
   - repeated copied complaint URLs count as one independence family.

5. **Recency matters**
   - older positives vs recent independent repeated defect reports.
   - recent evidence materially reduces quality confidence/rank.

6. **Ratings alone are insufficient**
   - 4.9 stars without qualitative evidence cannot create high quality score.

7. **Unknown price cannot win value label**
   - strong candidate with no verified/indicative price may rank on merit but not "best value".

8. **Relay isolation**
   - same public evidence with Relay offline/online produces identical public order, score, and tier.

9. **Bedding-specific quality**
   - stronger material/care/durability evidence can beat a cheaper weak-evidence alternative.

## 12. Complexity guardrails

To avoid quality degradation from architecture sprawl:
- each new module has one responsibility,
- ranking does not fetch network data,
- review trust does not parse product specs,
- preliminary ranking does not call price verification,
- value model does not alter Provider v2 offers,
- no circular imports among shopping modules,
- no single score is allowed to represent both merit and confidence,
- every new heuristic must have a deterministic regression test.
