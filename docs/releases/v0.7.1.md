# Korea Web Agent v0.7.1

## Live Verification Hardening

This release hardens the boundary between discovery and decisive purchase evidence without weakening the v0.7 Shopping Intelligence layer.

- Explicit non-Naver commerce URLs preserve the requested canonical product identity and required bundle components.
- Strong explicit-URL identity seeding is restricted to supported commerce hosts; arbitrary editorial URLs do not become exact targets from query text alone.
- Static seller pages promote shipping only when free or a fixed mandatory fee is deterministically tied to a shipping label; conditional, regional, collect-on-delivery, installation-dependent, extra-fee, and unlabeled promotional cases remain unresolved.
- Danawa, Enuri, and Naver Shopping comparison portals expose attributable downstream seller links to the default verification path. Search/comparison prices remain discovery-only until the downstream seller page verifies identity, price, shipping, and availability.
- Unrelated external advertising links are filtered before seller-expansion budgets are consumed.
- Relay diagnostics distinguish never-seen, online, and stale heartbeat states without exposing secrets, signatures, nonces, or queued payloads.
- The WideView QWGE43UT1 + EKWBYME78W(V3) benchmark rejects V2, body-only, metadata-only, and unknown-shipping decoys before decisive ranking.
- Feature-branch pushes run the same locked-dependency, production-audit, test, typecheck, and build CI gate used before merge.

## Final verification gate

The merge candidate is accepted only when the exact feature-head SHA has a fresh green CI run covering locked dependency installation, production dependency audit, the complete node:test suite, TypeScript typecheck, and production build. After squash merge, main CI, production dependency audit, Netlify production smoke, `/api/health` version `0.7.1`, and safe `/api/relay/status` diagnostics must all be verified again.
